# Как участвовать

Спасибо, что хотите помочь. Проект небольшой, правила простые.

## Сообщить об ошибке или предложить идею

Откройте [issue](../../issues/new/choose) и выберите шаблон. Для ошибки пригодится:
- версия BitrixBox (`bx version`) и ОС;
- команда, которую вы запускали, и её вывод;
- вывод `bx doctor`.

**Не публикуйте** пароли, содержимое `.env` и ключи. Об уязвимостях пишите по [SECURITY.md](SECURITY.md), а не в issue.

## Предложить изменение (pull request)

1. Сделайте форк и создайте ветку от `main`.
2. Внесите правку и проверьте её локально (ниже).
3. Опишите в pull request, что и зачем изменилось. Если меняется поведение, допишите `CHANGELOG.md` (раздел «Не выпущено»)
   и README.

### Проверки перед отправкой

```bash
shellcheck -x -S warning bx scripts/*.sh tests/*.sh      # стиль и типичные ошибки bash
for f in bx scripts/*.sh tests/*.sh; do bash -n "$f"; done
for f in scripts/php/*.php; do php -l "$f"; done        # синтаксис PHP (можно через docker run php:8.3-cli)
bash tests/e2e.sh                                       # полный цикл на пустом окружении, около 3–5 минут
bash tests/migrate.sh                                   # миграции на пустом окружении
```

Сквозной тест ставит Битрикс с нуля, поэтому запускайте его в чистой копии проекта (или после `bx reset`), с другими
портами при необходимости: `HTTP_PORT=8180 HTTPS_PORT=8543 bash tests/e2e.sh`.
GitHub Actions прогонит то же самое, а раз в неделю ещё и матрицу редакций и баз данных.

## Правила кода

- Скрипты — `bash` (совместимо с bash 3.2 на macOS: без ассоциативных массивов и `mapfile`) и должны проходить `shellcheck`.
- Сообщения пользователю — по-русски, коротко и по делу; ошибки должны подсказывать, что делать дальше.
- Опасные действия (удаление, смена паролей) — только после снимка (`bx backup`) и с понятным откатом.
- Всё, что внутри Битрикса, делайте через его API или штатные деинсталляторы, а не прямыми запросами к базе.
- Новая команда `bx`: функция в `bx` или скрипт в `scripts/`, строка в `bx help`, строка в таблице команд README и запись в CHANGELOG.

## Версии

[SemVer](https://semver.org/lang/ru/): исправления — `1.0.x`, новые возможности — `1.x.0`, несовместимые изменения — `x.0.0`.
Релиз делает мейнтейнер: меняет `VERSION`, дополняет `CHANGELOG.md`, ставит тег `vX.Y.Z`.
