# Перенос существующего сайта в BitrixBox

Гид по `bx import`, `bx pull`, `bx anonymize` и `bx upload-proxy`: как поднять у себя копию работающего сайта на Битриксе
и держать её свежей.

## Откуда переносить

| Источник | Команда | Что нужно |
|---|---|---|
| Резервная копия из админки | `bx import архив.tar.gz` | Настройки → Инструменты → Резервное копирование → «Создать резервную копию» (без шифрования). Части `архив.tar.gz.1`, `.2`… должны лежать рядом: команда подхватит их сама. Можно передать любую часть |
| Папка с файлами + дамп | `bx import /путь/к/сайту --sql dump.sql.gz` | Корень сайта (там, где `bitrix/` и `upload/`) и дамп MySQL (`.sql` или `.sql.gz`) |
| Сервер по SSH | `bx import user@host:/путь/к/сайту` | Вход по SSH (ключ, пароль или `~/.ssh/config`), на сервере `tar`, `gzip` и `mysqldump` (или `mariadb-dump`); `php` — желательно |

Нестандартный порт или ключ: `bx import ssh://user@host:2222/home/bitrix/www --ssh-opts "-i ~/.ssh/deploy"`.

По SSH на сервере выполняется только чтение (скрипт `scripts/remote/site.sh` передаётся через `ssh … bash -s`, на
сервере ничего не сохраняется): параметры базы берутся из `bitrix/.settings.php`, пароль передаётся `mysqldump` через
переменную окружения (не виден в списке процессов), дамп снимается с `--single-transaction` — без блокировки таблиц.
Сначала скачивается дамп и только потом что-либо меняется локально: если сервер недоступен, ваша копия не пострадает.

## Новый проект или существующий

Удобнее всего — отдельная папка на каждый сайт:

```bash
git clone https://github.com/razzhivine/bitrixbox.git shop && cd shop
./bx import deploy@shop.ru:/home/bitrix/www --anonymize --upload-proxy https://shop.ru
```

Если в папке ещё нет `.env`, `import` сам создаёт окружение без дистрибутива (это `bx init --edition none`). Параметры
окружения передаются так же, как в `bx setup`: `--php 8.2`, `--db mariadb-11.4`, `--http-port 8090`, `--project shop`.
Версию PHP и базы берите как на сервере.

Если окружение уже есть и в нём установлен сайт, `import` спросит подтверждение и сделает снимок (`bx restore` вернёт).

## Что меняется в перенесённом сайте

На диске (`bitrix/.settings.php`, `bitrix/php_interface/dbconn.php`):
- подключение к базе → контейнер `db` и параметры из `.env`; устаревший класс подключения `MysqlConnection` → `MysqliConnection`;
- кеш (memcache, redis, apcu) и сессии (redis, memcache, база) → в файлах;
- встроенная отправка почты через SMTP выключается — письма попадают в Mailpit;
- `cookies.secure` выключается, иначе на `http://localhost` не войти;
- в `dbconn.php` закомментированы настройки сервера: `BX_CACHE_TYPE`, `BX_MEMCACHE_*`, `BX_TEMPORARY_FILES_DIRECTORY`,
  `BX_SECURITY_SESSION_*`;
- `bitrix/.settings_extra.php` убирается (обычно там подключения боевого сервера).

В базе:
- адрес сайта (`server_name` и адреса сайтов) → `localhost:порт` — ссылки в письмах ведут на локальную копию;
- правила доступа по IP («Проактивная защита») выключаются — иначе админка закрыта;
- облачные хранилища переводятся в «только чтение» — новые файлы не попадут в боевой бакет;
- неотправленные письма из очереди удаляются.

Исходные файлы настроек сохраняются в `backups/import-<дата>/` (вне корня сайта; в них боевые пароли — не
публикуйте). Дамп из резервной копии после загрузки удаляется из `bitrix/backup/`, а сама папка закрыта в nginx.

Не меняется код: если в `init.php` своя функция `custom_mail`, письма могут уйти наружу — `import` об этом предупредит.
Ключи платёжных систем, интеграций и API в настройках модулей тоже остаются — проверьте их сами.

## Папка upload: перенести или брать с сайта

`upload/` часто весит десятки гигабайт. Вместо переноса:

```bash
bx upload-proxy https://shop.ru          # недостающие файлы nginx берёт с боевого сайта
bx upload-proxy https://shop.ru --save   # и сохраняет их в локальный upload/ (дальше — без сети)
bx upload-proxy off
```

Локальные файлы всегда в приоритете: загруженное у себя видно сразу. С `bx import` то же самое — флаг
`--upload-proxy https://shop.ru` (папка `upload/` тогда не переносится), а `--no-upload` просто не переносит её.

## Обезличивание

```bash
bx anonymize --dry-run      # что изменится (по таблицам)
bx anonymize                # снимок → обезличивание → пароль администратора
```

Меняется: почта (`user<ID>@example.test`), имена, телефоны, адреса, даты рождения, заметки и пароли пользователей
(логины-почты и логины-телефоны → `bxuser<ID>`, остальные логины остаются); строковые свойства заказов и профилей
покупателей (ФИО, почта, телефон, адрес, реквизиты; индекс и местоположение остаются), комментарии к заказам и история
их изменений; ответы веб-форм; подписчики и контакты рассылок; почта и IP в форумах, блогах, согласиях и голосованиях.
Удаляются: очередь писем, журнал событий, запомненные входы, ключи двухэтапной авторизации, сессии в базе, статистика посещений.

Пароли всех пользователей становятся недействительными; первому активному администратору задаётся новый пароль
(`--admin-password` — свой, `--admin-login` — другому администратору) и выводится один раз.

Не меняется: товары, каталог, инфоблоки, состав и суммы заказов, пользовательские поля (`UF_*`), данные в своих таблицах
и инфоблоках (например, заявки, которые сайт складывает в инфоблок), модули соцсети и мессенджера.

## Держать копию свежей

После `import` по SSH источник запоминается в `.env` (`IMPORT_SSH`, `IMPORT_SSH_OPTS`, `IMPORT_ANONYMIZE`):

```bash
bx pull              # свежая база с сервера (снимок перед этим)
bx pull --files      # и файлы сайта — кроме local/ (это ваш код в git) и upload/
bx pull --upload     # и upload/
```

Если копия была обезличена, `pull` обезличивает и свежую базу. `local/`, настройки подключения и ваши миграции не
трогаются; после `pull` можно сразу `bx migrate up`.

## Ограничения

- Зашифрованные резервные копии (`.enc`) не поддерживаются — сделайте копию без пароля.
- Сайты на PostgreSQL не поддерживаются (только MySQL и MariaDB).
- Многосайтовость с разными корнями (`bitrix/backup/sites/…` в архиве) не разворачивается: переносится основной сайт.
- Кодировка windows-1251: сайт переносится, но окружение рассчитано на UTF-8 — `import` предупредит.
- Версия PHP: в BitrixBox 8.2 и 8.3. Старый код, который на них не работает, придётся поправить.
