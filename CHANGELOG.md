## [1.2.1] — 2026-10-09

### Добавлено
- Автоподбор портов в `bx setup` / `bx init` / `bx import`: если стандартные 8080, 8443, 3306, 8025, 8081 заняты — другой
  программой, контейнерами другого проекта (в том числе остановленными) или записаны в `.env` соседних проектов
  BitrixBox — берётся тот же набор со сдвигом +10, +20 … Порты из флагов не меняются; если такой порт занят, будет предупреждение.

### Исправлено
- `bx setup --install --redirect` застревал на первом шаге мастера: перенаправление на https теряло POST-запросы мастера.
  Теперь при включённом перенаправлении мастер сразу работает по https.
- `bx https` сразу после перезагрузки nginx мог ещё отвечать старыми настройками — теперь ждёт завершения перезагрузки.

## [1.2.0] — 2026-10-08

### Добавлено
- `bx import` — перенос существующего сайта: из резервной копии Битрикса (`.tar`/`.tar.gz`, части `.1`, `.2` … склеиваются
  сами), из папки с дампом (`--sql`) или прямо с сервера по SSH (`user@host:/путь`, `ssh://user@host:порт/путь`).
  Создаёт окружение без дистрибутива (`bx init --edition none`), переключает сайт на локальную базу, кеш и сессии в
  файлах, выключает SMTP и secure-cookie, меняет адрес сайта, выключает правила доступа по IP, переводит облачные
  хранилища в «только чтение», чистит очередь писем, проверяет ответ сайта. Перед заменой сайта — снимок.
- `bx pull` — обновить копию с того же сервера: база, с `--files` — файлы (кроме `local/` и `upload/`), с `--upload` — и `upload/`.
- `bx anonymize` — обезличивание персональных данных (пользователи, заказы, формы, подписки, рассылки, комментарии,
  журналы) с паролем для первого администратора; `--dry-run` показывает объём по таблицам.
- `bx upload-proxy` — недостающие файлы `upload/` nginx берёт с боевого сайта (`--save` — и сохраняет локально).
- `docs/IMPORT.md` — гид по переносу; `tests/import.sh` и задача в CI: архив → импорт с обезличиванием → SSH с прокси → `pull`.
- Тест мастера установки на записанном диалоге (`tests/test_wizard.py`, запись `tests/fixtures/wizard-standard.jsonl`):
  проверяет драйвер без Docker; еженедельная матрица записывает свежий диалог и показывает, какие шаги и поля мастера изменились.

### Изменено
- Защищённые модули перечислены в одном месте: `scripts/protected-modules.txt` (раньше — дубли в `clean.sh` и `modules.php`).
- nginx закрывает `bitrix/backup/` (там резервные копии и дампы базы).

### Исправлено
- Обрыв связи при скачивании дистрибутива проходил молча: оставался недокачанный сайт, а установка продолжалась.
  Теперь дистрибутив скачивается в файл с тремя попытками, проверяется и только потом распаковывается; иначе — ошибка.
- `bx sql` показывал кириллицу вопросами (клиент без `utf8mb4`) и возвращал ошибку на запросы без вывода (`UPDATE` и т. п.).

## [1.1.0] — 2026-10-08

### Добавлено
- `bx migrate` — консольные миграции структуры Битрикса на основе sprint.migration 5.15.1: `install`, `add`, `ls`, `status`,
  `up`, `down`, `run` и остальные команды модуля. Перед `up` автоматический снимок (`--no-backup` отключает).
- `bx migrate status` — сколько миграций применено, сколько ждёт, есть ли «неизвестные».
- `bx modules` — список, установка, удаление и синхронизация модулей (`all`, `install`, `uninstall`, `required`, `sync`).
- `local/bx-modules.txt` — обязательные модули проекта: `bx clean` их не удаляет, `bx migrate up` ставит недостающие.
- `docs/MIGRATIONS.md` — гид по миграциям (работа, воспроизводимость с нуля, выкладка на сервер) и шаблон workflow для CI
  проекта: `docs/templates/bitrixbox-migrations.yml`.
- `tests/migrate.sh` и задача в CI: чистый Битрикс → три миграции (инфоблок со свойствами, разделом и элементом; hl-блок;
  группа и настройка) → `up`, повторный `up`, `redo`, `down`, возврат обязательного модуля.

### Изменено
- `bx clean` не удаляет модуль `sprint.migration` и обязательные модули проекта и не стирает их файлы.
- `tests/e2e.sh` и `tests/migrate.sh`: порты БД, почты и Adminer тоже переопределяются.

### Исправлено
- В консоли отключаются кеши инфоблоков (блок в `dbconn.php`, только `cli`): иначе тип инфоблока, созданный миграцией, не
  виден в том же процессе, и создание инфоблока падало с «Неверный тип блока».
- Консольные конструкторы sprint.migration падали на вопросах с множественным выбором (`TypeError`): `bx migrate install`
  расширяет тип возвращаемого значения в одном методе модуля.

## [1.0.0] — 2026-10-08

Первый стабильный релиз.

### Установка
- Одна команда с нуля: `bx setup --defaults --edition standard --install --clean` (около 1,5 минут):
  Docker, окружение, HTTPS, мастер установки Битрикса без браузера, очистка демо-данных.
- Мастер Битрикса проходится по HTTP (`bx install`): без регистрации продукта по умолчанию или с ней
  (`--register --reg-name --reg-surname --reg-email`); `--skip-updates` пропускает обновления в мастере.
- Редакции «Старт», «Стандарт», «Малый бизнес», «Бизнес»; MySQL 8.4 и 8.0, MariaDB 11.4 и 10.11; PHP 8.3 и 8.2.
- Неинтерактивная настройка флагами (`--defaults`, порты, база, администратор и др.), пароли БД по умолчанию случайные.

### Команды
- `bx update` — обновление платформы Битрикса (как «Обновление платформы» в админке), со снимком перед обновлением.
- `bx clean` — удаление демо-данных, остатков и модулей штатными деинсталляторами; защищены `main`, `security`, `fileman`, `ui`.
- `bx backup` / `bx restore` — снимки (база, файлы сайта, `local`) и откат одной командой.
- `bx https` — HTTPS с сертификатом mkcert или самоподписанным, редирект, свои домены.
- `bx doctor` — диагностика Docker, портов, сайта, HTTPS, кеша модулей, агентов, паролей и диска.
- `bx passwords rotate` — смена паролей БД в базе, `.env` и настройках Битрикса.
- `bx cron`, `bx debug`, `bx cache-clear`, `bx sql`, `bx php`, `bx open`, `bx version` и управление контейнерами.

### Окружение
- php-fpm, nginx, MySQL/MariaDB, cron для агентов Битрикса, Mailpit (ловушка почты) и Adminer.
- Файлы Битрикса лежат в томе Docker (на macOS файловая система не различает регистр, и обновления теряют файлы).
- Версии образов закреплены; порты базы, Mailpit и Adminer открыты только на 127.0.0.1.

### Проверки
- GitHub Actions: `shellcheck`, синтаксис PHP, `docker compose config` и сквозная установка с нуля на Linux.
- Вручную проверены все редакции и базы полным циклом (установка, очистка, диагностика, вход, откат) на macOS.

### Известные ограничения
- Windows и WSL не проверялись.
- Режима «у меня есть лицензионный ключ» нет (только регистрация по почте).
- `bx update` в CI не проверяется (нужна регистрация), проверен вручную.
